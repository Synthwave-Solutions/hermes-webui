## Qualifications and concrete improvements

These qualify reuse of the kit and its blanket claims; they are not proof that a current test made an unsafe request.

1. **Private HOME does not isolate every filesystem credential source.** Engine-root `.env` and machine-managed `/etc/hermes` may be loaded and even normalized by the real engine. The current absence checks above satisfy this prerequisite for this run. For a copied kit, require a fresh credential-free checkout and absent/explicitly isolated managed scope before startup. A future fixture-only fail-closed preflight, or an explicit private managed-directory override plus a blocked project dotenv fallback, would enforce this. Do not edit or delete an operator's real files to make a test pass.

2. **The Python guard is conditional on retaining its bootstrap environment.** `api/terminal.py:564–569` intentionally strips `PYTHONPATH` and `QA_ISOLATION_STATE` from embedded PTY shells. A Python launched there will not receive `sitecustomize` merely because the parent WebUI did. A native shell child, a credential CLI reached through `/bin/sh`, an absolute binary, a fresh `python -I/-S`, a Unix socket, or native networking is also outside the audit hook's guarantee. The existing terminal tests use explicit harmless synthetic commands; do not describe the kit as safely executing arbitrary untrusted code. This limitation is consistent with `os_sandbox: false`.

3. **`browser_network: loopback_only` is not universal browser enforcement.** Explicit `browser.newContext()` calls do not inherit the primary context fixture. For example, the additional signed pages in `resource-security.spec.ts:24` and `governance-administration.spec.ts:42` have no local routing guard. Other helpers add HTTP guards but omit WebSocket guards. `APIRequestContext` requests are not subject to browser page routing at all. Current scenario URLs are intentionally loopback, but a stronger reusable kit should wrap every context/request factory, block service workers as appropriate, and validate request and redirect destinations. Qualify this run as primary-context guarded plus reviewed loopback requests, not all browser contexts universally blocked.

4. **Cleanup covers known fixture process groups, not an independently verified process tree.** `run_full.py:98–108` sends TERM to three groups and escalates only when each direct leader fails to exit within five seconds. A leader can exit while another group member ignores TERM. Embedded PTYs (`api/terminal.py:593`) and engine background processes (`tools/process_registry.py:1203–1229`) create separate groups/sessions. The WebUI terminal's `atexit` cleanup is a graceful-path best effort; default SIGTERM is not Python `atexit`. In addition, SIGKILL or abrupt termination of the runner itself bypasses its `finally`. Individual scenarios close their own terminal/MCP resources, but final absence must be measured separately before claiming all descendants were removed.

5. **Source provenance is useful but not a complete execution-image lock.** The compared digest covers selected source extensions (`.py`, JS/TS/CSS/HTML, TOML/JSON/YAML/shell) and excludes generated `docs/qa/e2e` files. It does not cover ignored files, arbitrary extensionless executables, installed Python/npm dependencies or Chromium binaries. The recorded Git HEAD and tracked-diff hash are not themselves part of the unchanged-source boolean. Capture interpreter, dependency and browser versions alongside the receipt; qualify the digest as included application/test source, not all executable bytes. The CJS helpers are included by the general source digest even though the separate `test_source_sha256` list enumerates only Python scripts plus TypeScript/config.

6. **Failure receipts and export safety need precise wording.** A startup failure or interrupted runner may leave logs without `run.json`; absence is unknown, not a clean outcome. The export helper is an allowlist copier, not a general secret scanner: browser exception strings or a future audit attachment could contain sensitive values. Its current safe use depends on the synthetic fixture and selected screenshots. Keep all `e2e-state`, raw traces/videos and full logs private unless individually reviewed. The report's direct `RAW token` substring check is a specific regression indicator, not an exhaustive credential-leak detector.

7. **The all-click gate is an inventory gate, not a security or semantic certification.** `coverage_gate.py` does not bind imported results to matching source receipts and can merge reports from different revisions. It also relies on test outcome labels and ignores report-level errors when calculating `all_clicks_complete`. This does not make the current incomplete gate pass, but before ever claiming complete coverage, validate common source fingerprints, clean global errors, actual successful attempts and the exact story assertions. Never count unreachable or duplicate DOM controls as missing distinct workflows without inspecting their handlers.

8. **The README's frozen evidence is historical.** The current `docs/qa/e2e/README.md` still names the earlier 192-case release and says board tests do not launch live workers. The new supplement does launch real disposable local Kanban workers. Update those statements only from the final combined receipt. Retain the explicit synthetic Realtime/media and vendor-delivery boundaries.

The first three points are blockers to advertising this kit as a generally credential-isolated sandbox on an arbitrary developer machine. They are qualifications for the current controlled clean fixture, whose explicit preconditions were checked. There is no new application deployment blocker established by this source review.

## Safe final process census criteria

The runner has no persistent fixture PID manifest. Capture owned identities **while the run is alive**, then verify them again after exit; do not infer all children from vanished parent PIDs.

- For processes owned by the current UID, inspect environment in memory and output only match booleans. An exact `QA_ISOLATION_STATE == <this-run>/e2e-state` identifies normal Python/Node fixture descendants. `QA_STATE` is a corroborating marker, not a substitute for the run path.
- Embedded PTYs intentionally drop those QA variables. They retain exact `HOME == <this-run>/e2e-state/os-home`, `TMPDIR == <this-run>/e2e-state/tmp`, and `HERMES_WEBUI_TERMINAL=1`; use the exact private HOME as another ownership marker. Do not dump other environment entries.
- The initial server command contains the exact absolute `server_fixture.py`, repository, state and engine arguments; model and Realtime fixtures contain their exact script and allocated ports. Inspect arguments in memory and output only classification/path-match booleans or an argv hash. Do not publish arbitrary child command lines.
- Record PID, birth time, parent PID, process group/session, UID and sanitized role for matched roots and their descendants. On Linux, compare `/proc/<pid>/stat` field22 start ticks; on macOS use process creation time (such as `psutil.Process.create_time`) consistently. A reused PID is not the same process.
- Check detached descendants independently. The engine's private `<fixture-home>/processes.json` may corroborate background work using only `pid`, `pid_scope`, `host_start_time`, `systemd_unit` and exited status. Do not publish commands, chat IDs or tool payloads from that file. A missing checkpoint is not proof that no PTY/MCP/Chromium process survives.
- After cleanup, verify every recorded identity is gone or has a different birth time, then rescan exact private-home/QA markers for newly created descendants. Check the recorded loopback listeners are closed. Treat permission errors, incomplete identity reads or unexplained same-birth survivors as unknown/remaining work, not zero.
- No process should be signaled solely because its name is Python, node, sh, Chromium, MCP, or because its cwd resembles the repository. Any cleanup of a leftover needs exact owned identity verification; these notes authorize no process kill.
